# DELIVERABLE TEMPLATE — what the assistant returns per paste

Short, paste-ready, no preamble. Suraj **types** the turn text into Feather; he does not paste it.

---

## MODE START

```
TURN 1 of <planned N> — <domain> / <shape> / <register>

TYPE THIS:
<the opening prompt, exactly as it should be typed>

ARC: <turns 2-4 sketched in one line each, plus the planned end turn and why it ends there>
CAPABILITY: clean
HUMANIZATION: PASS
LOG: <domain · shape · register · length band> — rotated from last task on <axes>
```

## MODE COMPARE

```
TURN <n> of <planned N>

PICK: <A or B>   <NEAR-TIE if applicable>
WHY: <the decisive differential, quoted>
REASON FIELD (if you fill it in): <one casual sentence, varied wording>
VERIFY: <↳ must appear on the picked side before you continue>

TYPE THIS NEXT:
<the next user turn>

ANCHOR: "<the exact phrase from the chosen response this reacts to>"
EARNS ITS PLACE: <refines / constrains / challenges / next step>
CAPABILITY: clean
HUMANIZATION: PASS
COUNT: <n> of 10 minimum, 15 ceiling
```

## MODE BACKTRACK (turn <10 and the thread is exhausted)

```
BACKTRACK — do not add a filler turn

GO BACK TO: Turn <k>
REBUILD: <what to deepen there so the conversation reaches 10 naturally>
WHY: <what ran out, in one line>
```

## MODE END (turn ≥10 only)

```
END — turn <n> of 15

FINAL PICK: <A or B> — <differential>
THEN: send nothing further.
SUBMIT ORDER: Feather "Mark as Complete" → Vercel "Submit Task"
CHECKLIST: <PASS, or the lines still open>
```

---

**Never** include in a deliverable: rubric language, the losing response's content, the judge's
internal reasoning, or an explanation Suraj did not ask for.
